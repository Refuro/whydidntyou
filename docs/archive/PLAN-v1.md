# Plan: measuring method invention and concept invention (Phases 2–3)

Status: DRAFT for review. Nothing in this document has been run. The review question for a second reader is at the end.

## 0. What we are measuring, and what we already have

The discovery ladder (fixed vocabulary for the whole project):

| level | name | what the solver has to do | historical example |
|---|---|---|---|
| 1 | parameter discovery | known method, unknown setting; search a range | tuning a context model's order |
| 2 | method selection | default method fails; pick the right known method | switching contiguous → sparse contexts |
| 3 | method invention | no known method solves it; construct a procedure | Huffman's bottom-up merge (1952) |
| 4 | concept invention | define a new object before the problem is even tractable | the derivative; Shannon's entropy (1948) |

Phase 1 (`laggedRule`, `hiddenPeriod`) measures levels 1–2. Evidence from two real runs (seed 1, k=13): the model reaches level 2 within three attempts and succeeds or fails on whether its lag search range (12 vs 24) covers k. Phase 1's output is the **k-curve**: discovery rate as a function of k, which estimates the model's default search horizon. It is the control for everything below: when a model fails at level 3–4, the k-curve says whether search breadth alone could explain it.

This document plans levels 3–4.

## 1. The constraint that shapes everything

A frontier model has read every named method and every named concept. Novelty at levels 3–4 therefore has only three sources:

- **(S1) knowledge subtraction** — a model whose training stops before the breakthrough (vintage models: Talkie-1930, TypewriterLM-1913);
- **(S2) problems whose needed idea does not exist yet** — open problems; real novelty, but no ground truth, so no post-mortem;
- **(S3) domains in which the needed idea could not exist** because the domain was just invented.

Phase 1's mistake, named precisely: under S3 we minted a new *parameter* (lag 13) inside a known *concept* (sparse context). For level 4 the minted thing must be the concept. Phase 2 does that (S3). Phase 3 uses S1 on a real breakthrough. S2 is out of scope.

A second constraint: **a wall designed by someone who knows the solution method is a known-method wall.** The designer's knowledge must be limited to the generic strategy ("look for an invariant"), never the specific object. Phase 2's generator enforces this by minting the object randomly.

## 2. Phase 2 — hidden-invariant games (synthetic, levels 3–4)

### 2.1 Why invariants

The cleanest operational form of concept invention: a quantity nobody has defined, conserved under a set of rules, such that defining it collapses a class of intractable problems into a one-line check. The mutilated chessboard is the canonical human case; most people fail it, and those who succeed describe the same move — stop manipulating the board, define something *about* it. That move is structurally the derivative.

### 2.2 Domain definition

- **State:** a string over an alphabet Σ of size A (6–10 symbols). Length 8–40 for "small", 200–2000 for "large".
- **Rules:** a set of 6–14 local rewrite rules `u → v` (|u|,|v| ≤ 3), applied anywhere in the string, in either direction when stated as equivalences. Rules are generated *from* a hidden invariant so that every rule preserves it; the invariant is then never visible in the rule text.
- **Hidden invariant I:** a function state → value from one of the families in §2.4. Every rule satisfies I(left) = I(right).
- **Task:** given the rules and a labeled set of 200 state-pairs (reachable / not reachable), write `reachable(a, b) → boolean`, and optionally define `quantity(state)` — the object you believe is conserved.
- **Verifier:** accuracy on 1,000 held-out pairs, half reachable / half not, over *large* states (beyond brute-force search within the sandbox timeout). Pairs are balanced on length and symbol counts so no shallow feature leaks the label.
- **Ground truth without needing a complete invariant:** positives are generated by actually applying random rule sequences to a start state (reachable by construction); negatives are pairs with I(a) ≠ I(b) (unreachable by construction). This sidesteps proving I is a complete invariant.
- **Success criterion:** ≥ 95% accuracy on large pairs (chance 50%; brute-force on large states times out, so a BFS solver sits near chance on the large set).

### 2.3 Automatic novelty checks (the point of this design)

1. **Conservation check.** If the model defines `quantity(state)`, test it on 10,000 random (state, rule application) pairs. Conserved ⇒ it defined a real invariant. Also test whether it separates the negatives (i.e. is *the* invariant or an equivalent): agreement with I on random pairs.
2. **Generalization gap.** Accuracy on small pairs vs large pairs. A BFS-in-disguise scores high on small and near chance on large. A true invariant scores high on both. The gap is a one-number detector of "solved by search, not by concept".
3. **Named-method judge.** For every success, an LLM judge (human-checked sample) answers: "Is this approach a named technique in the literature?" and "Does the defined object have a standard name?" Standard parity/counting invariants ⇒ level 2; a constructed non-standard object ⇒ level 3–4.
4. **Derive vs enumerate annotation.** From the trajectory: did the model *enumerate* candidate quantities and test them (level 1 search inside the known strategy "look for invariants"), or *derive* the quantity from the rule structure (what the chessboard solution does)? LLM-judged with a human-checked sample. This distinction is the paper's central annotation.

### 2.4 The novelty dial (invariant families, ordered by enumerability)

| dial | family | why it sits there |
|---|---|---|
| D0 | parity of the count of one symbol | first thing anyone tries |
| D1 | weighted symbol-count sum mod m, hidden weights | enumerable: small weight space |
| D2 | order-sensitive: e.g. alternating-sign position-weighted sum mod m; or count of a specific ordered pattern mod m | not a function of the multiset; most enumerators assume multiset |
| D3 | non-commutative group-valued product: map symbols to elements of a small non-abelian group (S3, Q8), product over the string conserved, rules are group identities | not enumerable by "try sums mod m"; must be constructed from how rules commute |
| D4 | composite: invariant of a transformed state (e.g. of the run-length encoding, or of the string after a hidden merge rule) | requires defining an intermediate object first — two concept steps |

Generator guarantees per dial: at D2+ the invariant is *not* a function of symbol counts alone (checked by construction); at D3+ no sum-mod-m over counts or positions matches I on random states (checked empirically against an enumerator of ~10^5 candidates).

Prediction to pre-register: discovery rate is monotone decreasing in dial level; D0–D1 are near-ceiling (level 2 behavior); the drop between D1 and D3 is the measured boundary of invention.

### 2.5 Measurements (same harness, new columns)

- discovery rate per dial level, per model, with Wilson CIs
- conservation-check pass rate among successes (did it define a real invariant?)
- generalization gap distribution (search vs concept)
- share of successes judged "named method" vs "constructed"
- derive vs enumerate share
- hint-ladder minimal flip level per dial; a new content-free ladder for this family (e.g. "stop trying to move between states and ask what stays the same")
- post-mortem category + confabulation rate (claim vs log agreement)
- transfer: scaffold built from D1–D2 post-mortems, tested on D3 **and** on a held-out rule *style* (e.g. rules stated as equivalences vs as one-way rewrites) never used in tuning

### 2.6 Confounds and controls

- **BFS on test pairs.** Large states, sandbox timeout, generalization-gap metric.
- **Enumeration of invariants = level 1 in disguise.** The dial; the derive-vs-enumerate annotation.
- **Rule text leaking the invariant.** Rules are plain rewrites with no commentary; symbol names are arbitrary letters; rule order shuffled; include 2–3 "decoy" rules that are consequences of others.
- **Label leakage through shallow features.** Pairs balanced on length, symbol histogram, and edit distance.
- **Memorizing the 200 labeled pairs.** Test pairs disjoint and larger.
- **Prompt sensitivity.** Two paraphrases of the task prompt; report both.
- **Model knows the chessboard trick.** It does. That is level-2 knowledge ("look for invariants"); the dial measures whether that knowledge suffices.

### 2.7 Human baseline (small, optional but high value)

5 programmers, same prompt, same 12-attempt budget, same verifier, 90 minutes. Logged identically. Gives every table a human column and connects to the insight-problem literature (invariant discovery is hard for humans too; the comparison is the point, not the absolute rate).

### 2.8 Implementation (repo)

- `src/domains/invariantGame.js`: `make(seed, {dial})` → rules, labeled pairs, test pairs, `secret: {family, params}`, `quantity(state)`.
- `src/verifiers/reachability.js`: accuracy scorer + conservation checker + generalization gap. (`sandbox.js` becomes contract-agnostic: each domain declares its contract and scorer.)
- `prompt.js`: per-domain task text; `<new_object>` must be accompanied by `function quantity(state)` when claimed.
- `selftest.js`: BFS solver must fail on large pairs; sum-mod-m enumerator must pass D0–D1 and fail D3–D4; reference solver passes all.
- `prereg/invariantGame.md`: key moves (KM1 "ask what the rules preserve", KM2 "define a state-level quantity", KM3 "verify conservation on the rules", KM4 "construct from rule structure, not enumeration"), predictions, success criterion.
- `hints/invariant-content-free.json`.
- Analysis: extend `report.js` with the dial curve and the new columns.

## 3. Phase 3 — vintage model on a real breakthrough (S1, levels 3–4)

### 3.1 Target: optimal coding, 1928 → 1952

Model: Talkie-1930 (13B, pre-1931 text, open weights; base and instruction-tuned variants; a larger version was planned for summer 2026 — verify at talkie-lm.com before planning around it).

In-context prerequisites, all pre-1931: Hartley (1928) on quantifying information, Nyquist (1924), elementary probability, logarithms, Morse code as an existence proof that frequent symbols get short codes. Phrased in 1930 vocabulary ("message", "signal", "telegraph", no "bit", no "entropy").

Targets:
- level 3: construct a prefix-free code with minimum average length given symbol frequencies (Huffman 1952). Verifier: average code length vs optimum.
- level 4: define a single quantity, a function of the frequencies alone, that lower-bounds the achievable average length (Shannon 1948). Verifier: does the defined quantity equal H up to base/scale on random distributions? (Same conservation-style automatic check as Phase 2.)

### 3.2 Protocol

Same harness: attempt loop, verifier, hint ladder (1930-safe wording), post-mortem. Memory = full.

Controls:
- **Leakage check first.** Query Talkie on "entropy", "bit", "Shannon", "Huffman", "information theory". Expect no post-1930 content. Record.
- **Floor check.** Give a modern model the identical 1930-vocabulary prompt. If it solves it instantly, the prompt is adequate; the gap between Talkie and modern is capability + knowledge, not prompt.
- **Capability control.** Give Talkie a level-1/2 problem of similar difficulty whose method existed in 1930 (e.g. a frequency-table coding task where Morse-style assignment suffices). If it fails that too, Phase 3 is floor-limited and reported as such.

### 3.3 Expected status

Reported as a case study (n = 1 model, ≥ 30 trials), not as the main sample. Its value is the demonstration that the synthetic ladder corresponds to a real historical breakthrough with real prerequisites and real ground truth.

## 4. Experimental design (all phases)

- Models: ≥ 2 families (Anthropic + one other; `llm.js` needs a second backend). Temperature 1.0 unless stated. Memory `full`. Output cap 16k.
- Per condition: ≥ 10 seeds × 3 repeats for the paper; 3 × 2 for pilots. Budget 12–15 attempts per trial.
- Every trial row records: model, domain, dial/k, seed, repeat, success, attempt of success, distinct ideas, tokens, seconds, and the automatic novelty checks.
- Pre-registration frozen before each phase's first real run; addenda only.
- Human spot-check: 30 idea-clusters, 30 post-mortem classifications, 30 named-method judgments, 30 derive/enumerate labels; report agreement.

## 5. Analysis plan and figures

1. **The ladder figure.** Discovery rate (with CIs) at levels 1, 2, 3, 4 — from the k-curve (1–2), the dial (2–4), and Phase 3 (3–4 historical). One figure, one sentence: where models stop.
2. **k-curve.** Rate vs k; estimated search horizon per model.
3. **Dial curve.** Rate vs dial; the D1→D3 drop; conservation-check and generalization-gap overlays.

6. **Transfer.** Scaffold contrast on held-out dial/style, percentage points with CI. The headline.
7. **Human column** wherever §2.7 is run.

## 7. Open questions for the reviewer

1. Is the generator's guarantee (rules derived from I, I never visible) sufficient to keep the designer's knowledge out of the wall, or can the *form* of the rules leak the invariant family? Propose a concrete leakage test.
2. Is "≥ 95% accuracy on large pairs" the right success criterion, or should success require the conservation check to pass (i.e. require a defined object)? Argue both ways.
3. Does the derive-vs-enumerate distinction survive scrutiny as a measurement, or is it too judgment-laden? What would make it objective (e.g. counting candidate quantities tested per attempt)?
4. Is D3 (non-abelian group product) really non-enumerable for a model that knows group theory, or is "map symbols to S3 and check" itself a stock move? If so, what is the next rung up?
5. Phase 3: is optimal coding the best 1930→1952 target, or is there one with cleaner prerequisites and a sharper level-4 object?
6. Sample sizes: is 10 × 3 per condition enough to resolve a D1→D3 drop of ~40 points? Compute.
7. What is the strongest objection a skeptical reviewer would raise to the claim "this measures invention, not search", and does the plan already answer it?
